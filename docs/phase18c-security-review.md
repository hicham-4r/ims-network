# Phase 18C — targeted security and resource hardening

Baseline: Phase 18C source bundle, 2026-11-24. Phase 18AB1 installed. This batch does not claim a complete penetration test or production readiness.

## Changes and rationale

- Explicit public Better Auth HTTP route allowlist for the existing password-only app, including the reset link callback and session/sign-out endpoints. Unused endpoints (including direct password confirmation) are not exposed; owner confirmation still calls the authenticated server API directly. New auth features must intentionally extend the allowlist. Mutating auth requests require the configured exact origin and JSON (empty sign-out/session allowed), with a 16 KiB bounded body and no compressed payload. Existing CAPTCHA and distributed rate limits remain. Reset submissions receive the recovery limiter too. Requests with invalid headers do not spend Redis commands.
- Email ownership is still NOT required for sign-up or membership. Email-based reset delivery is restricted to legacy verified addresses; no flag is fabricated. Unverified members should contact the owner; a secure manual recovery process is **not implemented**. Retire older deployments sharing the database and allow previously issued one-hour reset tokens to expire; the new delivery check does not invalidate existing tokens. Do not use the reset flow to establish identity or owner authority. Existing verified-address reset delivery still requires a working sender. Test generic recovery responses and legacy reset callback on an isolated database. Never log reset links. Do not deploy until this behavior is accepted.
- Explicitly disable Better Auth cookie cache; existing DB session checks and per-notice socket authorization remain. No auth/session cache is introduced. Owner role and atomic audit/state mutations remain unchanged.
- Existing account/profile reads skip redundant conflict inserts. Missing rows still use conflict-safe fallback. No schema changes; no stale shared authorization cache. The normal established-member context avoids two write attempts. Real DB and CPU savings require measurement.
- Avatar upload: exact configured origin, single auth guard, five attempts per ten minutes per member (fixed window, Redis fail closed); reject before image decoding or Blob writes. Avatar reads use one auth guard and retain active-viewer/target checks. Admin moderation: 30 attempts per five minutes per admin, fail closed. Existing owner-only limiter remains unchanged. These limits spend Redis commands for protected mutations, not polling; no extra Redis reads for regular browsing. Fixed windows can allow bursts across a boundary.
- Remove raw client-side route error logging; retain generic error UI. Add enforced same-origin form-action; broader CSP remains report-only pending real browser checks. No claim that platform/provider logs are secret-free.

## Dependency release gate (not performed by patch)

Lockfile inspected: Better Auth and Drizzle adapter 1.7.14, Next 16.4.6, React 19.3.0, Drizzle ORM 0.45.4, ws 8.23.0, sharp 0.35.5. The registry audit could not run in the review environment (DNS/network unavailable). No dependency versions or lockfile are silently modified. Run `npm audit --omit=dev` and `npm audit` locally; report severity counts and affected package paths, not credentials. Do not run `npm audit fix --force`. Review Better Auth advisory GHSA-fvxx-76fc-893x (fixed in 1.7.16; current app does not configure secondary session storage or cookie cache). Upgrade matched Better Auth and adapter versions only after checking published versions and reviewing lockfile changes. Do not call this audit complete until known applicable vulnerabilities are resolved or documented.

## Live acceptance, protected isolated Preview only

1. Existing owner sign-in/sign-out, session retrieval, new signup CAPTCHA (dummy keys only for protected Preview), pending restriction, approval and member login. Real CAPTCHA keys and hostname/action validation before public launch.
2. Same-origin POST works; forged/missing origin, unexpected auth endpoint, oversized/chunked body and unsupported content type reject. Test sign-out and session refresh in browser. Reset requests remain generic; no unverified-address delivery. A controlled verified legacy mailbox with functional provider exercises the actual email link and token submission.
3. Owner promotion/demotion with password confirmation, revocation, non-owner denial, audit. Admin moderation and avatar limits, including Redis outage, on controlled test accounts. Avoid destructive actions against real users. Verify avatar upload/read and denial for unauthenticated/inactive accounts.
4. Established account/profile reads, newly created rows and concurrent fallback. PostgreSQL stays authoritative. Existing conversations, message send/read, reconnection, cross-user delivery and role/account restrictions. Relay disabled for general admin tests; explicitly enable only on short controlled relay trials.
5. Measure Upstash commands, Neon reads/writes, Blob operations and Vercel CPU/memory/transfer at baseline and under load. No 100-user/free-tier guarantee. Per-instance WebSocket cap does not provide a distributed connection cap. CSP enforcement, manual recovery, retention, real Turnstile setup and production WebSocket policy remain launch gates.
