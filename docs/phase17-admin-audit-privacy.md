# Phase 17 — Admin dashboard, audit and moderation privacy

## Scope
- `/admin`: authenticated ACTIVE ADMIN only; counts by account state, including legacy UNVERIFIED. Counts use existing Next.js Cache Components, 30-second revalidation / 60-second expiry (server cache; client router may lag). Cache contains numbers and fixed labels only. Admin actions invalidate the tag; new registrations become visible in the live queue immediately and counts may lag briefly. Counts are not used for any authorization decision. Instance-local caching effectiveness is not guaranteed; measure it on Preview.
- `/admin/accounts`: pending by default, explicit ALL/status, literal case-insensitive name/email prefix, stable user-ID keyset order, 20 items plus one lookahead. No full user export. Search strings are URL parameters: do not enter secrets; avoid sharing admin URLs/logs with personal data. Rows and details are not server-cached. Count/group scans and prefix search can still be expensive as data grows; inspect plans and consider indexes if measured workload requires it.
- `/admin/accounts/[id]`: minimal profile and account state; no credential hashes, tokens or private chats. Audit history link filters by target. Each read has its own ACTIVE ADMIN check; not merely a layout/UI check.
- `/admin/audit`: read-only account transitions, 20 + 1 lookahead, keyset by exact UTC microsecond timestamp and ID. No raw JSON or reason in the audit viewer; from/to values are allowlisted. Actor ID and current name, target ID, action and time; names can change or disappear. Audit rows remain in PostgreSQL, written by the existing atomic transition SQL, alongside session revocation when required. Not a tamper-proof external audit system.
- All four actions require affirmative confirmation; approval requires independent eligibility review. ADMIN target changes and self changes are blocked in SQL/service. Existing role/state checks and compare-and-set remain, with database-time actor state/session checks. The existing action-level authorization and transaction semantics remain. Concurrent requests still use PostgreSQL snapshot semantics; no claim of globally instantaneous revocation.
- `/privacy`: accurate messaging/administrator disclosure. No administrator conversation viewer, no `ADMIN_VIEWED_CONVERSATION` event because no such access is introduced. Members, including admins, remain subject to conversation membership checks. Infrastructure operators may technically access database contents; no E2EE claim.
- No added provider, Redis traffic, package dependency, schema change, migration, role promotion, automatic approval, or change to email verification/password recovery. Resend reset delivery and unverified email ownership remain known limitations; see ADR 0006. Phase 16 realtime and messaging implementation untouched except the user-facing privacy link and dashboard navigation.

## Preview acceptance (major milestone only)
Use the existing isolated Preview database and two controlled users; do not operate on real members. Verify deployment protection. Close old relay tabs and retire only the specific previous disposable relay deployment when done. Relay stays off in the ordinary Phase 17 Preview unless explicitly needed for a short re-test.

1. Anonymous, pending, suspended and ordinary ACTIVE MEMBER: `/admin`, `/admin/accounts`, `/admin/accounts/[known-id]`, `/admin/audit` must redirect/deny without account or audit data. Try direct URLs and server-action replay from a nonadmin session (no tokens in logs). UI hiding alone is not evidence. Test sign-out and switching browser accounts.
2. ADMIN: dashboard counts, pending list, all/status filters, literal `%`/`_` search, invalid/oversized/duplicate query params, missing ID. Use enough isolated fixtures to span two pages if available; no duplicate/missing rows on unchanged data. Audit cursor ties/microsecond preservation; reject wrong-filter cursors. Under concurrent changes, pagination is not a snapshot; reset filters to refresh.
3. Register a controlled new account without email verification. Confirm pending, cannot access member routes. Try approve without the checkbox (including submitted false value): deny with no state/audit change. Approve after checking eligibility: ACTIVE, one audit row (actor, target, from/to, UTC time). Refresh counts. Replay same action: no extra transition/audit. Test reject on a separate pending fixture, suspend/restore the approved test account; reasons required for reject/suspend, sessions revoked; re-login after restoration. Verify no admin can change their own or another ADMIN account through crafted form input. Do not attempt state changes on a real administrator.
4. Verify normal chat still works; an admin who is not a participant must not read another conversation via guessed IDs. There is no `/admin/conversations` reader. Check `/privacy` and messaging privacy link.
5. Record real Vercel CPU, memory and invocation deltas, Neon query load and Upstash command usage; do not infer capacity or free-tier guarantee from passing local tests. No added Redis calls in Phase 17 code. Observe idle and repeated admin reads separately.

Local structural/unit checks are not live authorization, database, deployment or cost tests. No production deploy until later security and privacy gates are complete.
